# 🌱パパッと食材チェック🍚
## 1. サービス概要

- 「パパッと食材チェック」は、離乳食で試したい食材から、市販ベビーフードを簡単に検索できるWebアプリです。

- 保育園入園予定・入園中の0歳児を育てるママパパの、  
限られた時間の中でたくさんの食材チェックを進める必要がある課題に対して、  
試したい複数食材から効率的にベビーフードを購入しチェックを進めていく手助けをします。

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

子ども（0歳）の保育園入園説明会で、100種類以上の食材が書かれた用紙が配られました。

保育園の給食で初めて食材を口にすることがないよう、家で試してきてねという「食材チェック」表でした。

子どもが園で給食をいただくためには、食材チェック表のチェックを埋める必要がありますが、難点が2つ。

- 食材チェックはアレルギー発症のリスクを踏まえ、病院が空いている平日の午前中に行うことが通例。

- お肉やお魚、果物などのアレルギー発症リスクの高いものは、どの食材で発症したか判別するために1日1種類までしか試せない。

入園まで2週間ほどと試せる期間が限られる中で、チェックを埋めるためには、アレルギー発症リスクの低いお野菜や調味料系をまとめて試すにはベビーフードが最適でした。

しかし、ベビーフードは商品数が多く、原材料も商品ごとに異なります。

スーパーやドラッグストア、公式HPで、一つ一つ原材料表示を確認しながら、「にんじんと生姜を一度に試したいけど、豚肉はまだ…」と照らし合わせて商品を探す作業は非常に時間がかかりました。

子どもが寝ている短い時間や買い物中にスマホで調べることも多く、「もっと簡単に探せる方法はないのかな」と強く感じたことが、このサービスを作ろうと思ったきっかけです。

### 2-2. なぜそれが「気になった」のか

私は、

- 頼れるものは頼り尽くしたい
- そのための情報収集はしっかり行う
- 自分で新しい仕組みを作るのが好き
- 料理は苦手

という性格です。

子育て支援系のアプリを複数使っていますが、離乳食に関するアプリは手作りレシピ関連か試したことのある食材を記録するアプリのみ。

食材チェックは月齢に応じて進める必要がある物もあり、0歳児入園予定・在園しているママパパは働きながら進めることもしばしば。

流行りのAIが代わりに対応してくれることはありません。

0歳児入園・共働きの家庭が増えている世の中で、
できるだけ周り（ベビーフード）に頼りながら効率的に食材チェックを進めたい！！と思うこの体験は、多くの保護者が経験している課題ではないかと考えました。

---

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

試したい複数の材料からベビーフードを探す手間がかかる点

### 3-2. 本当に解決したい課題は何か

- 手作りではなく周りに頼ることで素早く食材チェックを進めたいのに、適切な商品を探すのに時間がかかるから
- 月齢や子どもによって、試せる食材は一気に試したいが、食べられない食材が含まれている商品は避けたいという複雑な検索条件となるから
- 「試したい食材」と「商品の原材料」を照合する仕組みが存在しないから

→ 本当に解決したい課題：保護者が、ベビーフード選びに悩む時間を減らし、効率的に食材チェックを進められる状態にすること。

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

年齢設定：
  - 年齢・性別：30歳・女性
  - 理由：初めて出産・育児を経験する世代（日本国内における第1子出生時の母親の平均年齢）のため。

生活・状況設定：
  - 生活・状況：
    * 0歳（3ヶ月〜11ヶ月）を育てている
    * 保育園に0歳児入園を考えている
    * 離乳食はベビーフードにも頼っている
    * 平日はママのワンオペ率高め
  - 理由：毎日の育児で時間に余裕がなく、短時間で商品を選びたいというニーズが高いため。

環境設定：
  - 環境：
    * 調べるのはスマホ中心、子どものねんねの時間に限られる
    * 子連れでの買い物なので、ゆっくりと商品を比較しながら買い物はできない
  - 理由：複数食材を選択するだけで候補を表示することで、どのベビーフードを購入するかすぐに見当をつけられる

### 4-2. 自分とユーザーの距離

以下のうち、最も近いものを選んでください。

- 自分自身

→ 自身の子どもの食材チェックを進める中で感じた不便さを解決するために企画したサービスのため

### 4-3. 実際に使われる可能性について(需要・存在確認)

◼️最初に使ってくれるユーザ想定

    - 保育園入園前・在園中の0歳児の保護者
    - 0歳児を育てる友人
    - SNSで離乳食情報を収集している保護者

◼️思い出すタイミング

    - ベビーフードを買うとき
    - 新しい食材を試したいとき

◼️今の生活で代わりに使っているもの

    - Google検索
    - メーカーサイト
    - 商品裏面
    
どれも「複数食材から複数メーカ横断で商品を検索する」という体験は提供していない！！！

## 4-4. ユーザーがサービスを導入して利用するまでのイメージ(導入・継続の流れ)

1. SNSや検索でサービスを知る
2. 会員登録なしで利用開始
3. 試したい食材を選択
4. 該当するベビーフードを確認
5. お気に入り登録し、スーパーで見返す（MVP）
6. Amazon・楽天リンクから購入
7. 試した食材／日付の一覧を保育園に提出（MVP）

月齢が進むにつれて食べられる食材が増えるため、継続的に利用されることを想定しています。
自分の子どもが通う保育園にアプリケーションを紹介し、毎年入園される保護者にアプリを使ってもらうイメージもしています。

## 8. このアプリの懸念点とその対策
### 懸念点①

- 何が問題になりそうか：商品情報の更新が追いつかない可能性がある。
- なぜそう思うか：ベビーフードは定期的に新商品や終売が発生するため。
- そのために考えている対策：CSV管理によるデータ更新を容易にし、将来的には管理画面から更新できるよう改善する。

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- フレームワーク：Ruby on Rails 8
- DB：PostgreSQL
- デプロイ先：Render
- 画像：Amazon Product Advertising API（予定）
- CSV：Ruby CSV

---

### 10-2. 技術選定の比較検討

| 候補 | 採用/不採用 | 理由 |
| --- | --- | --- |
| Ruby on Rails | 採用 | RUNTEQの学習内容を活かし、Webサービス開発の基礎を身につけるため |
| MySQL | 不採用 | Railsとの親和性やRenderでの運用実績を考慮し、PostgreSQLを選択した。 |
| React | 不採用 | 学習コストが高く、まずはRails単体でサービスを完成させることを優先したため。本リリース以降に導入を検討 |

- 今回チャレンジしたい点

    * Controller・Model・Viewの責務を意識した設計（Controllerはデータ取得、Viewは軽い表示加工、Modelは業務ロジック）
    * has_many :through を用いた多対多リレーションの設計
    * CSVを利用したマスタデータ管理
    * OR検索と一致件数によるランキング表示

- 不安な点

    * Amazon Product Advertising APIの利用条件や実装難易度
    * 商品データの継続的なメンテナンス
    * 今後データ量が増えた際の検索パフォーマンス

---

### 10-3.キャッチアップ不足の懸念

キャッチアップ不足の段階では以下の懸念点があります。

1. **完成までのハードルが高い**

Ruby on Railsを中心に開発を進めますが、Amazon Product Advertising APIとの連携や、検索ロジックの最適化など、未経験の技術領域も含まれています。そのため、開発中は技術調査や検証に一定の時間が必要になると考えています。

2. **Issueの見積もりが難しい**

初めて実装する機能については、調査時間や試行錯誤を含めた見積もりが難しい可能性があります。そのため、MVPではコア機能（食材検索・商品表示・詳細表示）に優先順位を置き、小さな単位でIssueを分割しながら進める方針です。

まずはRailsとHotwireでサービスを完成させ、保守性の高いMVC設計を身につけることを優先します。その後、Reactをキャッチアップし、技術的な検証を行った上で導入を検討する予定です。
